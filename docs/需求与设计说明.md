# 餐厅经营游戏挂机助理 —— 完整需求与设计说明

> 本文档面向需要**重新实现或移植本程序**的 AI 模型/开发者。包含：游戏背景与机制、完整功能需求、视觉识别算法细节（含阈值参数）、自动化流程、已踩过的坑、验收标准、资源文件清单。参考实现在 `src/`（可直接运行，也可作为伪代码级别的需求描述来重写）。

---

## 1. 项目背景

一款 PC 端餐厅/酒馆经营类游戏（窗口约 2555×1494，实测基准分辨率）。玩家经营店铺，顾客到店后需要**手动把顾客拖到匹配的桌子**入座，顾客消费后产生金币需要点击收取。游戏分铜/银/金三个房间（难度递增），一局游戏结束后出现结账界面。本程序是一个**屏幕视觉识别 + 模拟鼠标操作的挂机助理**：自动拖顾客入座、收金币、切房间，游戏结束时自动停止。

## 2. 游戏机制（逆向得知的规则，实现必须遵守）

1. **顾客等待**：底部顾客区最多 8 个槽位，每位顾客耐心约 40 秒且**同时计时**，超时离店（有客流流失赔偿）。耐心条颜色从绿→黄→红渐变，红色时原来的亮绿检测法会失效。
2. **房间**：左上角有铜/银/金三个房间门（点击切换），右上角有「铜之间/银之间/金之间」房间牌（用于判断当前房间）。**房门图标下方常显数字「已入座人数/容量」**（如 `0/20`、`5/16`、`0/12`），表示该房间空位情况。房间使用顺序：**银→金→铜**。
3. **桌子与店员**：每局开始前玩家给各房间安排店员，**开局后桌下标签条（店员擅长风格）固定不变**；有的桌子无店员（无标签条）。桌子可坐多人，坐满后不再有空位。
4. **拖拽才显示的信息**：只有当顾客被鼠标左键**按住拖出顾客区**（拖出一半也算）时：
   - 空桌子上出现「+」标记（有空位的桌子才显示；金房间是**粉红色+**，铜/银房间是**白色+**）
   - 桌子下方显示标签条（店员擅长风格，彩色图标）
   - 被按住的顾客头顶显示**偏好图标**（拖拽点上方约 180px 处）
   - 与顾客偏好匹配的桌子会出现**绿色荧光描边**（游戏官方匹配信号，但**绿光不代表有空位**，满桌也可能发光）
5. **匹配规则**：顾客偏好 ∈ 桌台标签 才是正确匹配（另有「任意匹配模式」见功能 F7）。
6. **结束**：一局结束后弹出结账界面（挑战成功/合计收入），底部中央有「**结束营业**」按钮——看到它即本局已结束。
7. **金币**：场内散落金币堆，右下角有「收集场内所有金币」一键按钮。

## 3. 功能需求清单

| # | 功能 | 需求描述 |
|---|------|---------|
| F1 | 悬浮控制窗 | 置顶小窗：开始/结束按钮、自动切换房间复选框、任意匹配模式复选框、框选游戏区域按钮、实时日志框 |
| F2 | 全局快捷键 | **F8=开始、F9=结束**（系统级 RegisterHotKey，游戏全屏无焦点时也有效）；按钮文字标注快捷键；重复触发无副作用 |
| F3 | 自动入座 | 循环识别顾客 → 按住拖出 → 识别偏好+桌标签 → 拖到匹配桌放下；耐心最少的顾客优先；单轮最多 6 位防卡死 |
| F4 | 收金币 | 每 6 秒点一键收集按钮，再逐个点场内剩余金币堆 |
| F5 | 自动切房间 | 按银→金→铜顺序轮换（20 秒定时 + 两种触发：当前房间满员提前切、无匹配桌时切）；切房时优先选**有空位**的房间 |
| F6 | 入座核验与满桌拉黑 | 拖放后核验顾客是否真坐进去（原槽位仍有顾客且总数未减=失败）；同桌 30 秒内连续 2 次失败→临时拉黑（匹配时排除），成功入座清零，过期自动恢复 |
| F7 | 任意匹配模式（可选项） | 勾选后跳过偏好/标签识别，有空位的桌就直接放（仍排除拉黑桌）；运行中切换即时生效，选择持久化到配置 |
| F8 | 游戏结束自动重启 | 每 2 秒检测「结束营业」按钮，出现即自动执行**重启链**：点结算页「结束营业」→ 游戏首页「开始营业」（右下）→ 开业准备页「开始营业」（右下）→ 进入新一局继续挂机；重启后清空本局状态（房间/桌台标签/拉黑表）；全程状态轮询（按页面模板去重，防页面切换慢时同页重复点击漏掉下一页），总超时 45 秒，超时放弃并停止 |
| F13 | 事件弹窗随机选择 | 游戏中会随机弹出事件弹窗（全息弹窗/美味时间等，标题文案不定），**中下部有 2~3 个蓝色选项按钮竖排**；检测到后**随机点一个选项**，等约 2 秒弹窗自行消失后继续游戏。与文案无关的颜色几何识别（见 4.9），不依赖模板 |
| F9 | 实时日志框 | 按行追加带时间戳的日志，自动滚底，超 300 行删最旧；**长文本必须自动换行且不能撑宽窗口** |
| F10 | 框选游戏区域 | 首次使用需框选游戏画面，持久化到 config.json |
| F11 | 紧急停止 | 鼠标甩到屏幕左上角立即停止（pyautogui failsafe） |
| F12 | 随机偏移 | 所有点击/拖拽落点带 ±8px 随机偏移（模拟真人，避免检测） |

**速度要求（用户多次强调）**：顾客耐心只有 40 秒且同时计时，单个顾客「拿起到入座」必须 ≤ 0.5 秒。参考实现实测 ≈0.45s/位（pickup 0.15s + 等待 0.05s + 截图 40ms + 桌位识别 10ms + drop_at 0.16s）。

## 4. 视觉识别设计（核心）

所有坐标基于基准分辨率 2555×1494，其他分辨率按比例换算。截图用 mss（BGR numpy），识别用 OpenCV。

### 4.1 顾客识别 `find_customers(img)`
- 顾客区是固定 UI：8 个卡片槽均宽分布（2555 宽下首槽 x=0.1425w、间距 0.0945w、耐心条 y=0.9654h、拖拽点 y=0.9405h）
- 只对底部条带做 HSV（性能），采样耐心条**左段** 75×14 窗口（填充从左开始）：`hue≤60 或 ≥168` 且 `S≥95、V≥150` 的彩色像素 ≥50 判定有人——兼容绿/黄/红温全状态
- 返回按剩余耐心升序（填充越少越急，优先安排）

### 4.2 空桌识别 `find_empty_tables(img, room)`
识别「+」标记，多模板并集：`table_plus.png`（铜/银白+）、`table_plus_gold.png`（金粉+）。搜索区域限中央（y 10%~75%，x 3%~97%）。三级提速：
1. **房间样式锁定**（`_ROOM_PLUS_HIT`）：每房间「+」样式固定，某样式命中过一次后本会话只用该模板
2. **桌位缓存**（`_TABLE_CACHE`）：房间内桌位不动，缓存 (模板名, 尺度, 桌点列表)，后续只做**局部窗口验证**（模板半宽+24px 窗口，阈值 0.72），~10ms；**每 5 次做一次全图刷新**防拖拽卡片遮挡漏检
3. 全图路径：缓存尺度 + 半分辨率粗筛(0.70)→原分辨率局部确认(0.72)，零命中回退多尺度扫描

实测：最坏情况 3564ms → 快路径 8-10ms。匹配阈值 0.72，去重半径 40px，返回点向下偏移模板高 20%（≈桌心）。

### 4.3 桌台标签识别 `read_table_tags(img, tx, ty)`
- 桌点下方 +113px、±95×32 窗口，HSV 色相统计。**双饱和度阈值规则**（区分标签色与背景装饰，关键参数）：
  - `green`: cnt(S≥80) ≥ 500
  - `red`: 1200 ≤ cnt(S≥80) ≤ 4500（**上限防金房间红地毯整窗误报**；>4500 判定整窗地毯，同时压制 pink）
  - `navy`: cnt(S≥80) ≥ 900 **或** cnt(S≥110) ≥ 400（灰蓝凳子在银房间会造成 FP，双阈值分离）
  - `skyblue`: cnt(S≥80) ≥ 2000 或 cnt(S≥110) ≥ 600
  - `pink`: (cnt(S≥80) ≥ 1500 或 cnt(S≥110) ≥ 400) 且未被地毯压制
- 标签每局固定 → `main.py` 缓存 `{room: {(gx,gy): frozenset}}`（60px 网格键），识别过一次不再重复识别

### 4.4 顾客偏好识别 `read_customer_pref(img, cx, cy)`
拖拽点上方 ~180px（cx, cy-0.28h 附近）、±32×32 窗口，同一套 `_tags_from_region` 色相统计，返回标签名或 None。

### 4.5 绿光补充 `find_glow_tables(img)`
荧光绿 HSV `(35,120,200)~(75,255,255)`，连通域 ≥600px 取质心。**只作兜底**（标签匹配失败才扫）：绿光代表"偏好匹配"不代表有空位。需排除拖拽点附近 160px 的顾客卡片青边框 FP。

### 4.6 房间数字识别 `read_room_counts(img)`
- 门下「已入座/容量」白字：带 y 25.2%~29%h，三个门中心 x≈0.048/0.112/0.182w ±70px
- 二值化 `V≥200 且 S≤70` → 连通域分割（bh≥20、bw≤40 滤噪声）→ 归一化 24×32 → 与 `templates/digit_*.png` 模板匹配（阈值 0.55）→ 按 `/` 分隔符拆出 N/M
- 识别不出 → None（保守处理，不阻断切房逻辑）

### 4.7 房间牌/门/按钮
- `detect_current_room`：右上角房间牌模板（room_sign_*.png）
- `find_room_doors`：左上角门图标模板（door_*.png），限定横向搜索带
- `find_collect_button`：右下角一键收集（collect_btn*.png，阈值 0.70）
- `find_end_business`：底部中央（x 25%~75%、y 70%~100%）找「结束营业」按钮（end_business.png）。**模板必须按基准分辨率预放大**（源截图 1920 宽 → 2555 需 ×1.33，否则得分仅 0.45）；尺度自适应 `rel=图宽/2555`±5%，半分辨率粗筛(0.85)→原分辨率确认(0.80)；7 种宽度 1152~2555px 全过，未命中 ~40ms
- `find_start_business`：右下角（x 60%~100%、y 75%~100%）找「开始营业」按钮——游戏首页和开业准备页两个页面按钮样式几乎相同但尺寸略异，用两套模板（start_biz_home.png / start_biz_prep.png）取最优；同一套尺度自适应算法；**返回 (cx, cy, 命中模板名)** 供重启链按页面去重；自身页得分 0.99+，交叉页仅 0.61~0.65（阈值 0.80 分离良好）；1920/2304/2555px 宽全过，未命中 ~40ms

### 4.9 事件弹窗检测 `find_event_popup(img)`
游戏随机事件弹窗（标题文案各不相同），共同特征是**中下部有 2~3 个蓝色圆角选项按钮竖排居中**。与文案无关的颜色几何识别：
- ROI：x 20%~80%、y 50%~95%
- 蓝色按钮 HSV `(95,80,150)~(112,220,245)`（实测 H≈102、S≈103-132、V≈183-188）
- 组件过滤：宽 0.15~0.55w、高 0.04~0.12h、填充率 >0.5（实测按钮 1146×120 @2560 宽 = 0.448w×0.080h）
- **检出 ≥2 个按钮才认定弹窗**——单按钮的「结束营业」「开始营业」按钮被此规则排除（实测结算画面/开业准备页各只有 1 个，正确不误报）
- 命中返回选项中心列表（按 y 升序），主程序随机点一个、等 2 秒；耗时 5~14ms

### 4.8 匹配决策（每轮）
```
顾客偏好 ∈ 桌台标签 → 候选桌（排除拉黑桌/本轮已试桌）
无匹配 → 绿光补扫（同样排除拉黑桌）
仍无 → 原位松开(drop_cancel)，顾客自动回队列；8 秒冷却后切房间
有匹配 → 拖到最近的候选桌
```

## 5. 自动化流程

```
App(tkinter, 主线程)
 └─ Worker(threading.Thread)  每轮 _tick:
    1. capture 截图
    2. 每 2s 检测「结束营业」→ 命中则执行自动重启链（见 F8）后继续挂机
    3. 开局识别当前房间（房间牌）
    4. 收金币（6s 间隔）
    5. 满员快切：当前房间数字 n≥m → 直接换房
    6. _assign_customers：最多 6 位/轮（pickup 拖出 → _scan_held 扫描 → 匹配 → drop_at）
    7. 定时轮换房间（20s）
    8. 核验上一次入座（复用本轮截图，零额外开销）
动作层 actions.py：pyautogui，PAUSE=0（关键提速），moveTo 分步平滑 + 随机偏移
```

关键函数签名（重写时对齐行为即可）：
- `actions.click(x,y)` / `pickup(x0,y0,x1,y1,duration=0.08)` / `drop_at(x,y,settle=0.03)` / `drop_cancel()` / `_jitter(±8px)`
- `vision.capture/ find_customers/ find_empty_tables/ read_table_tags/ read_customer_pref/ find_glow_tables/ read_room_counts/ detect_current_room/ find_room_doors/ find_coins/ find_collect_button/ find_end_business`

## 6. 已踩过的坑（重写必读）

1. **cv2.imwrite/imread 中文路径静默失败**——必须 `cv2.imencode(...).tofile(path)` / `np.fromfile + imdecode`
2. **mss 实例绑定创建线程**——模块级单例跨线程复用（停止后再开始）会 `BitBlt failed`；必须按线程重建 + grab 失败重建重试
3. 桌位局部验证窗口必须 ≥ 模板半宽+24px，固定 ±48px 边距会裁掉 110×114 模板导致全部验证失败（得分 0.33）——且单次 bench 会被"最后一次恰好是全图刷新轮"掩盖，**必须逐次断言**
4. 金房间「+」是粉色不是白色，需要独立模板；金房间红地毯会把 red/pink 色相统计打爆（红地毯双阈值规则见 4.3）
5. 绿光 ≠ 有空位（满桌也发光），不能只靠绿光匹配；「+」和标签只在拖拽时显示
6. 耐心条红温时亮绿检测失效 → 用"彩色填充"判定
7. pyautogui 默认 PAUSE=0.1s 会把拖拽拖到 1 秒级，必须归零并用 moveTo(duration) 分步
8. Python 3.13 无 tkinter，环境用 3.10；CPU OpenCV 足够（无需 GPU）
9. tkinter 长文本：状态栏 Label 加 `wraplength` 限宽，否则撑宽整个窗口

## 7. 环境与运行

- Windows + Python 3.10（venv），依赖：`opencv-python mss pyautogui numpy pillow`
- `config.json`：region（框选区域）、loop_interval 0.3、collect_interval 6.0、room_cycle、room_cycle_interval 20.0、any_match
- 启动：`python src/main.py` → 框选游戏区域 → F8 开始

## 8. 验收标准

1. 拖拽状态样本 `samples/拖拽状态_铜房间_按下顾客后.png`：空桌识别结果与参考实现一致（局部验证快路径 = 全图扫描）
2. `samples/房间截图_*.png` 三张：房间牌识别正确；门下数字读出（含 0/20、5/16、8/16、0/12 字样）；无「结束营业」「开始营业」误报
3. `samples/结算画面_结束营业.jpg`（及其 0.6x~1.33x 缩放版）：全部命中「结束营业」检测
4. `samples/游戏首页_开始营业.jpg`、`samples/开业准备页_开始营业.jpg`：两页均命中「开始营业」检测（返回的模板名分别为 start_biz_home / start_biz_prep）；交叉误报 < 0.7
5. 重启链状态机仿真：结算页停留多帧、首页切换慢多帧两种场景，均按序点完 结束营业→首页→开业准备 并重置状态
6. `samples/事件弹窗_*.png` 两张：均检出 3 个选项按钮；房间/首页/开业准备/结算画面零误报
7. 真机验收：单顾客拿起到入座 ≤ 0.5s；满桌不反复拖（最多 1 次失败即拉黑）；银→金→铜顺序轮换；点结束后再开始无 BitBlt 错误；一局结束后自动重启进入下一局；事件弹窗随机选择后游戏继续
8. 日志框长文本不撑宽窗口
